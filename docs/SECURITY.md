# Безопасность

- В frontend только URL и publishable/anon key. Дополнительная проверка клиента отсекает очевидный secret/service-role ключ, но не заменяет контроль состава build.
- Auth предоставляет Supabase. Legacy localStorage с открытыми паролями/PIN очищается при запуске. Токен сессии хранится стандартным Supabase SDK; не хранится пароль пользователя.
- RLS включён на каждой прикладной public-таблице; grants дополнительно запрещают запись заказов, изменение phone/id профиля, чтение заявок обычным пользователям.
- Admin роль находится в `private.admins`. Профиль и клиентский state не позволяют её изменить. `is_admin()` проверяет authenticated UID.
- Security-definer функции имеют пустой search_path, полностью квалифицированные таблицы, явную проверку Auth/Admin. EXECUTE отозван у PUBLIC и возвращён только нужной роли.
- `place_order` требует аккаунт, проверяет размер корзины и целое количество, блокирует остатки, вычисляет цену в integer dirams и сохраняет заказ одной транзакцией. Rate limit: до 10 новых заказов/час/аккаунт. Idempotency: unique(user_id,request_id).
- Кошелёк/оплата не симулируются. Состояние платежа нельзя выставить через браузер.
- Контактная форма принимает сообщения только через Edge Function с ограничением тела, honeypot, проверкой полей и DB quotas. CORS не является аутентификацией; rate limits остаются обязательными. После роста трафика добавить CAPTCHA/инфраструктурные лимиты.
- Product images публичны по назначению. MIME/размер ограничиваются bucket. Чужие пользователи не могут загружать фото; SVG исключён.
- React экранирует строки, HTML-инъекции не используются. Номера/Telegram handles проверяются перед построением ссылок.
- Файлы `.env*`, `.secret`, runtime metadata исключены из Git. `.env.example` не содержит значений.

## Ограничения

Неподтверждённый телефон — только логин, не доказательство личности. Необходимо безопасное восстановление аккаунтов перед широким публичным использованием. Admin доступ особенно желательно усилить MFA в следующем релизе. Браузерные токены требуют осторожности со сторонними скриптами; MVP не загружает внешние analytics/widgets.

Static Pages не поддерживает произвольные серверные security headers. Для строгого CSP/headers потребуется поддерживающий их хостинг или CDN. Не ослабляйте RLS ради удобства интерфейса.

Локальная схема проверяется в PostgreSQL/PGlite с тестовыми ролями и служебными Auth/Storage таблицами. Это не проверка реального SMS, Supabase gateway или Edge deployment. После настройки проекта выполните интеграционные шаги из SUPABASE_SETUP.
