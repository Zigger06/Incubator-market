# Проверка качества интерфейса — 21 сентября 2026

Второй проход выполнен поверх существующей архитектуры. HashRouter, Supabase services, защищённые RPC и GitHub Pages сохранены.

## Найденные причины и исправления

- Цвет и фон `:root` были фиксированными, а dark mode менял только переменные дочерних компонентов. Теперь `html/body/#root` и компоненты используют единую палитру `styles/theme.css`. Локальные `.dark .component` исправления удалены; цвета текста, фона, карточек, полей, placeholder, статусов, иконок и фокуса централизованы. Сохранённая тема применяется до первого рендера.
- Пункт категорий дублировал каталог. В верхнем меню теперь главная, каталог, о нас, доставка, гарантия, контакты. Категории остаются в каталоге, на главной и в footer.
- Таджикские термины приведены к заданию: «Рамз», «Такрори рамз», «Бақайдгирӣ», «Ба қайд гирифтан», «Нишон додани рамз»; связанные ошибки тоже исправлены. Русский checkbox теперь явно говорит «Показать пароль».
- Связь раньше исчезала при пустых настройках. Общая кнопка открывает доступную панель WhatsApp/Telegram/формы специалиста. Отсутствующий контакт отмечен как недоступный, ложные адреса не создаются. На mobile панель открывается снизу, поддерживает Escape, цикл Tab, возврат фокуса и блокировку прокрутки фона.
- `features/contact/links.ts` формирует локализованные WhatsApp сообщения: название, вместимость, цена, URL, выбранный вариант и количество. ContactProvider передаёт тот же контекст глобальному виджету. Контакты берутся из `site_settings` с fallback к `config/site.ts`.
- Форма обращения получила канал ответа и обязательное Telegram-имя при выборе Telegram. Клиент, Edge Function и дополнительная SQL-миграция проверяют контракт. Сохранение показывается только после успешного ответа; при ошибке данные остаются в форме.
- Для одного результата каталог использует широкую карточку, для двух — две колонки; есть блок помощи. Пустое избранное содержит иконку, объяснение и переход в каталог. Поиск без совпадений имеет отдельный текст и сброс фильтров. Русское количество склоняется: 1 товар / 2 товара / 5 товаров.
- Регистрация имеет прямой маршрут `#/auth?mode=register`, отдельные ошибки входа/регистрации/OTP и блокирует изменение полей во время запроса. Недоступность backend показана ненавязчивым пояснением.
- Дополнительно исправлены: skip-link, который раньше менял hash-маршрут; контраст этой ссылки в dark mode; доступность мобильного раскрытия фильтров; наложение toast и плавающей кнопки; слишком широкая контактная кнопка поверх карточек desktop.

## Фактически выполненные проверки

Браузер: локальный headless Chromium 153 + Playwright. Облачный Browser вернул `ERR_BLOCKED_BY_CLIENT` для managed preview. Согласно заданию использован headless fallback. Production `dist` загружается через локальный перехват файлов в браузере, без внешних запросов и без подмены исходников приложения.

**224 состояния:** 7 страниц × 2 темы × 2 языка × 8 ширин (320, 360, 375, 390, 430, 768, 1024, 1440). Для каждого состояния созданы screenshots, проверены DOM, отсутствие горизонтального переполнения, JavaScript ошибок и контраст отрисованного текста по computed styles. Порог — 4.5:1 для обычного текста и 3:1 для крупного. Disabled элементы исключены из автоматического порога. Это целевая проверка текста, а не полная сертификация WCAG или тестирование всех screen readers.

Скриншоты всех семи страниц просмотрены в обеих темах; отдельно просмотрены desktop Home/Catalog, регистрация на планшете, карточка товара на mobile, пустое избранное, каталог с 1–2 товарами и мобильная панель связи. ## Что требуется владельцу

1. Если первая миграция уже применена, выполнить **только** `supabase/migrations/202609200002_contact_preferences.sql`, затем заново deploy функции `contact`. Порядок и команды — в [SUPABASE_SETUP.md](SUPABASE_SETUP.md).
2. Указать реальные WhatsApp/телефон/Telegram в настройках магазина. Пока они пусты, виджет честно показывает недоступные каналы.
3. Если сайт ещё в demo, добавить публичные Supabase URL и publishable key в GitHub Repository Variables и перепубликовать. Секрет service role не нужен frontend и не включён в него.
4. На подключённом проекте подтвердить реальную отправку обращения и SMS, если включено подтверждение номера. Live backend/SMS в рамках этого прохода не проверены и не имитируются как рабочие.

На GitHub Pages сохраняются `base=/Incubator-market/` и hash routes. Источник публикации должен быть **GitHub Actions**, чтобы legacy Jekyll workflow не перезаписывал собранный сайт.
