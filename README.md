# Incubator Market

Расширяемый интернет-магазин инкубаторов для Таджикистана: React + TypeScript + Vite, Supabase PostgreSQL/Auth/Storage/Edge Functions, GitHub Pages. Интерфейс на таджикском и русском, цены в TJS.

## Что реализовано

- Главная, категории, каталог с поиском, фильтрами в URL, сортировкой, grid/list и порционной выдачей.
- Страница товара: галерея, характеристики, варианты, количество, связанные товары.
- Корзина в браузере, избранное (для аккаунтов — Supabase), вход/регистрация по телефону и паролю, дополнительный SMS шаг при включённом подтверждении.
- Заказ после входа: проверка цены/остатков в БД, резервирование, повторная отправка без дубликата, история заказов.
- Кабинет с профилем и адресом; админка с товарами, категориями, вариантами, фотографиями, остатками, заказами, сообщениями, пользователями и настройками.
- Контакты WhatsApp/Telegram/телефон из настроек, публичная форма с отдельной Edge Function и ограничением частоты.
- Миграция, RLS, seed, автоматические тесты и workflow публикации.

**Без настроенного Supabase работает явно обозначенный демонстрационный каталог.** Покупки, регистрация и отправка сообщений не симулируются. Фотографии товаров и коммерческие цены нужно добавить владельцу. Фото цыплят на главной — тематическая иллюстрация, не изображение товара.

## Локальный запуск

Нужен Node.js 22+ и npm. Lockfile хранится в Git.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Открыть адрес, который выводит Vite, с `/Incubator-market/`. Для разработки в корне можно задать `VITE_BASE_PATH=/` в окружении команды. Маршруты имеют вид `/#/catalog`, поэтому refresh и прямые ссылки работают на статическом хостинге без серверных rewrite.

```bash
npm run lint
npm test
npm run build
npm run preview
```

## Подключение реальной базы

Полная пошаговая инструкция: [docs/SUPABASE_SETUP.md](docs/SUPABASE_SETUP.md).

1. Создать Supabase project. Применить `supabase/migrations/202609200001_store.sql`, затем `supabase/seed.sql` через SQL Editor или CLI.
2. Включить Phone provider, signup, минимум 8 символов пароля. Для простого входа без SMS отключить подтверждение номера. Если оно включено, настроить SMS provider; UI поддерживает ввод кода.
3. Развернуть Edge Function `contact`, настроить разрешённый origin и salt согласно инструкции.
4. В `.env.local` для разработки и в GitHub Repository Variables для сборки внести только `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` (publishable/legacy anon).
5. Зарегистрировать владельца, выдать ему admin через SQL, заполнить контакты и товары в `/admin`.
6. Перезапустить workflow после изменения переменных.

Не вводите `service_role`, `sb_secret_…`, пароль БД или private API key в `VITE_*`. Эти значения попадают в публичный JS даже при передаче через GitHub Secrets. Публичный ключ защищается RLS, не сокрытием.

## Архитектура

[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) описывает границы модулей. Компоненты не принимают решения об окончательной стоимости заказа и не назначают роли. Эти операции принадлежат PostgreSQL functions.

## Безопасность и проверки

[docs/SECURITY.md](docs/SECURITY.md) описывает права, потоки данных и ограничения. Тесты PostgreSQL выполняются в PGlite с имитацией служебных схем Auth/Storage; реальный Supabase Auth, Storage HTTP API и Edge runtime требуют интеграционной проверки после подключения проекта.

## Границы первого релиза

- Без онлайн-эквайринга, гостевых заказов, MFA и самостоятельного восстановления пароля. Платёж согласуется с продавцом.
- Корзина локальна этому браузеру; серверное избранное доступно только после входа. Гостевое избранное не копируется автоматически в аккаунт.
- Заказы резервируют остаток сразу. Отмена администратором возвращает его один раз. Доставленный/отменённый заказ закрыт для смены статуса.
- Для текущего небольшого ассортимента загружается до 1000 опубликованных товаров, на экране по 12. Перед ростом выше этого объёма перевести сервис каталога на серверную фильтрацию и курсоры. Админские списки также ограничены 1000 строками.
- Hash routing надёжен для Pages, но ограничивает SEO отдельных карточек. Для полноценных индексируемых страниц нужен будущий SSG/SSR.
- Нативный WebMCP поиск включается только в поддерживающем его браузере; экспериментальная возможность не нужна обычным покупателям.
